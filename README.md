# Dr. Richa Singh — academic website

Source for the personal academic website of Dr. Richa Singh, Professor of
Biotechnology. Built with [Quarto](https://quarto.org) and published via GitHub Pages.

- `index.qmd` / `research.qmd` / `teaching.qmd` — the three pages
- `papers/` — one page + one PDF per publication
- `teaching/` — course-note PDFs · `tools/` — interactive HTML tools
- `_templates/paper-template.qmd` — starting point for a new paper page
- `_templates/publication-block.md` — copy-paste block for adding a paper to the list
- `images/headshot.jpg` — her portrait, square, used on the Profile page
- `cv/richa-singh-cv.pdf` — **scrubbed** CV. The mobile number, personal Gmail and
  both named referees have been removed. The unedited original lives in
  `private/source-assets/` and must never be copied here as-is. If the CV is
  refreshed, scrub it again before it goes into `site/`.

Rendered output (`_site/`) is generated by Quarto and is not committed.

## Design

The look is **"Ledger"** — direction B of `planning/design-directions-v1.html`,
chosen 27 Aug 2026. Sans-serif, one column about 70 characters wide, publications
as hairline-ruled rows with the year and version badge in a fixed left column.

All of it lives in **`styles.scss`**, which has two halves:

- `scss:defaults` — the variables. Colours and typefaces are changed here.
- `scss:rules` — the layout. Leave it alone unless the design itself is changing.

Two constraints the design depends on:

1. **The accent colour must not be green or amber.** Those two belong to the
   version badges (green = Open Access, amber = Accepted manuscript); an accent
   in either colour makes the badges stop meaning anything.
2. **Every paper entry keeps the same five elements in the same order** (v2 §3.4).
   The `::: pub` wrapper is what puts the year and badge in the left column —
   don't edit those lines.

`styles.css` is the old placeholder stylesheet. It is no longer loaded and can be deleted.

## Domain

`drrichasingh.in`, registered 27 Aug 2026.

- `_quarto.yml` → `site-url: "https://drrichasingh.in"`. This is what makes every
  paper page's `citation_pdf_url` an absolute address on the real domain — the
  tag Google Scholar needs. Verified rendering correctly.
- `CNAME` in this folder holds the domain for GitHub Pages. **Do not delete it.**
  Quarto copies it into `_site/` on every render, which is what stops a deploy
  from silently dropping the custom domain.
- DNS still to be set at the registrar: four A records to `185.199.108–111.153`,
  four AAAA records to `2606:50c0:800{0..3}::153`, and `www` as a CNAME to
  `<username>.github.io`.

## What is published — currently ONE PAGE, live

The site went live on 30 Aug 2026 with **only the Profile page**. `research.qmd`
and `teaching.qmd` are not finished, so they are neither rendered nor published,
and the navbar has no tabs — just her name.

The whole switch is the render list in `_quarto.yml`, under `project:`:

```yaml
  render:
    - index.qmd
  resources:
    - "!*.qmd"
```

`resources: "!*.qmd"` is not decoration. Without it Quarto copies unrendered
`.qmd` files into the published site as project resources, and the unfinished
pages become readable in public. Leave it in place whatever else changes.

**To publish a page when it is ready**, do two things together: add it to the
render list, and uncomment its entry in the navbar block below `collapse-below`.
A page with no navbar entry is unreachable; a navbar entry with no page is a 404.

**To go back to the holding page**, change the render list to `- holding.qmd`.
`holding.qmd` is still in this folder, unchanged, and carries its own `noindex`
tag so search engines never record "Coming soon" as the site's content. It never
needs editing.

### Two things not to "tidy up"

- **The navbar entries point at `.html`, not `.qmd`.** That is deliberate. With
  `.qmd` hrefs, Quarto copies the page sources into the published site.
- **If you ever switch the render list to a wildcard** (`"*.qmd"`), you must also
  exclude `holding.qmd` with `"!holding.qmd"`. Otherwise it builds to
  `index.html` as well and collides with the real homepage, which silently breaks
  the build — the CV, the photo and the sitemap stop being published.

### Verified at launch

Rendered and inspected before going live: the published site contains
`index.html`, `CNAME`, the CV, the headshot, `robots.txt`, `sitemap.xml`,
`search.json` and the theme assets, and **no `.qmd` source of any kind**.
`robots.txt` permits indexing, nothing carries `noindex`, the sitemap lists only
`index.html`, and no local link on the page is broken. The CV contains no mobile
number, no personal email and no referees; the headshot carries no EXIF data.
